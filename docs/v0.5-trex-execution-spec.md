# council-diff v0.5 — execution-before-review (TREX pattern) spec

**Source motivation:** Greptile/TREX (GitHub trending 2026-06-17) — AI code reviewer that *executes* code in a sandbox before each voice reviews it. Reduces hallucinated review comments on code that compiles but breaks at runtime.

**Status:** spec only. Implementation gated on Alex confirming v0.5 ships this vs deferring to v0.6.

---

## Why

council-diff today does static review only. The 5 voices read the diff, return verdicts, the Oracle adjudicates. A class of failures that escapes this loop:

1. Code that is **syntactically valid + type-checks** but throws at runtime (e.g., off-by-one in a loop, JSON path mismatch, missing await).
2. Code that **passes a single happy-path test** but breaks on a boundary case the diff did not visibly modify.
3. Code where the **voices disagree on guessed runtime behaviour** because none of them actually ran it.

TREX's insight: cheap sandboxed execution before review gives every voice the same ground truth, eliminating the speculative reasoning that produces hallucinated review comments.

## What

Add an opt-in `--with-execution` flag on the `council-diff` CLI. When enabled:

1. Spin up a sandbox container (Docker / Firecracker / Apple Container).
2. Apply the proposed diff.
3. Run the test suite (auto-detect from `package.json` / `pyproject.toml` / `go.mod`).
4. Capture: pass/fail counts per test, runtime stack traces, coverage delta (optional).
5. Pass that execution report to every voice as additional context.

The Oracle's adjudication now has access to "what actually happened" in addition to "what the diff says."

## Schema additions

`council-diff` adds two new fields to the per-voice input:

```ts
interface ExecutionReport {
  ran: boolean;                  // true if the sandbox spun up successfully
  test_summary: {
    total: number;
    passed: number;
    failed: number;
    skipped: number;
  };
  failed_tests: Array<{
    name: string;
    file: string;
    stack: string;               // truncated stack trace
  }>;
  coverage_delta: number | null; // % point change in coverage, if measurable
  sandbox_duration_ms: number;
  sandbox_errors: string[];      // any spin-up or eval errors
}

interface VoiceInputV05 {
  // existing fields
  diff: string;
  prompt: string;
  voice_id: string;
  // new
  execution?: ExecutionReport;
}
```

Voice system prompts get a new instruction: *"If `execution` is provided, ground your review in the actual test outcomes, not in your assumed behaviour. Do not flag concerns whose only evidence is your speculation about runtime behaviour when the execution report contradicts that speculation."*

## Sandbox options (ranked by speed-of-implementation)

1. **Docker-in-Docker (DinD)** — works on any GitHub-Actions runner. Slow (~15s spin-up) but universal. Default for v0.5.
2. **Firecracker** — sub-second spin-up. Requires Linux host with KVM. v0.6 candidate.
3. **Apple Container** — macOS native, fast. Limits cross-platform parity. v0.6 candidate.
4. **Node.js `vm` module + worker_threads** — no container at all; in-process eval. Brittle, security-questionable. Reject.

v0.5 ships #1. The Sandbox interface is abstracted so #2 and #3 can swap in later.

## Security model

Sandbox containers:

- No network egress by default (whitelist for specific test dependencies via flag).
- Read-only mount of project root + writable `/tmp` for test artefacts.
- 60-second wallclock timeout per test run; kill-and-report after.
- Memory cap (default 512 MB) to prevent test-runaway from crashing the host.
- No host filesystem access except the diff target tree.
- No access to ANTHROPIC_API_KEY or other secrets — execution report is post-test, not during.

## Non-goals (deliberately out of scope for v0.5)

- Full CI replacement. council-diff is a review primitive, not a CI runner.
- Static analysis fusion. The execution report is runtime-only. SAST integration is v0.7.
- Iterative test repair. The voices read the report; they do not propose fixes that the sandbox then re-evaluates.
- Multi-language polyglot. v0.5 supports the dominant test runner per language (jest / pytest / go test). Niche frameworks deferred.

## What this gives council-diff competitively

Greptile is a closed-source SaaS. council-diff with the execution-before-review pattern is the OSS equivalent, plus the 5-voice deliberation + Brier audit Greptile does not have. Positioning copy: *"the code reviewer that runs your tests, has five opinions about the result, and Brier-audits which opinion was right next week."*
