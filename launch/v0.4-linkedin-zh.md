# LinkedIn - 中文版 (v0.4.0)

> 发布时间:LinkedIn EN 发出后 24h。

council-diff v0.4.0 ship 了。这是一次纯定位调整,代码一行没改,只重写了 README。下面是为什么。

Karpathy 4 月在 Sequoia AI Ascent 把软件分成三个时代:

- Software 1.0:你手写的代码。
- Software 2.0:训练好的神经网络。
- Software 3.0:对 LLM interpreter 写 prompt。

他给 agentic engineer 的工作描述就一行 bullet 列表:写规格 · 看 diff · 写测试 · **搭评估闭环** · 管权限 · 隔离 worktree · 守质量。

council-diff 从 v0.1 (6/8) 开始,这些原语就一直在 ship,只是当时没用这套词:

- 5 个 persona brief = 规格(每个 persona 都明写 bias 声明)
- 5 个 voice verdict 并排 = diff
- `agreement_score` (0-1) = 测试
- **Brier 审核模块** = 评估闭环(每个 voice 在 resolution 时打分,跟踪 30/90 天校准度)
- `safeMode` (强制 zero-retention Sonnet 4.6) = 权限
- Fable 5 Oracle 裁决 = supervisor

v0.4.0 在 README 写了一张 6 行映射表,把 Karpathy 每个 bullet 映射到 council-diff 的对应 primitive。

为什么改框架不加 feature:

1. 库已经完整了。33 条测试绿。Brier 审核、Oracle override、retention disclosure 都早就 ship。
2. 框架不对。"5-voice AI council" 听起来像 Claude 的 wrapper。"多 persona AI agent 的 OSS 评估闭环" 才是真正的品类。
3. Anthropic 6/9 ship 了 "advisor strategy" beta,跟 council-diff v0.3.0 Oracle 是同一个模式,晚 6 个月。这个模式现在是行业标配。council-diff 是唯一一个底下还跑 Brier 校准层的 OSS 实现。

教训:产品对了、增长慢的时候,先看框架再看 feature。

MIT,npm。可以直接扔进 `.claude/skills/` 目录自动 load。council 一次 ~$0.03,加 Fable 5 Oracle 一次 ~$0.10。
