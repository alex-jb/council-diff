# LinkedIn - English (v0.4.0)

I shipped council-diff v0.4.0 today. It is a positioning release. Zero code changed since v0.3.1. Here is why I think that was the right call.

Andrej Karpathy gave a talk at Sequoia AI Ascent in April. He split software history into three eras:

- Software 1.0: explicit code you write.
- Software 2.0: trained neural networks.
- Software 3.0: prompting an LLM interpreter.

His agentic engineering job description was one bullet list: design specs, supervise plans, inspect diffs, write tests, create evaluation loops, manage permissions, isolate worktrees, preserve quality.

council-diff had been shipping those primitives since v0.1 (June 8) without naming them that way. Persona briefs were the spec. Side-by-side voice verdicts were the diff. The agreement_score was the test. The Brier audit module was the evaluation loop. The Fable 5 Oracle was the supervisor. The retention disclosure plus safeMode was permissions.

v0.4.0 rewrites the README to make the mapping explicit. A 6-row table in the README points each Karpathy bullet to the corresponding council-diff primitive.

Why rewrite the frame instead of adding features:

1. The library was complete. 33 tests pass. The Brier audit, the Oracle override, the retention disclosure were all shipped.
2. The frame around the library was wrong. "5-voice AI council" sounds like a wrapper around Claude. "OSS evaluation loop for multi-persona AI agents" is the actual category.
3. Anthropic shipped "advisor strategy" (beta) on June 9, six months after council-diff's v0.3.0 Oracle release. The pattern is now industry-standard. council-diff stays as the OSS implementation that ships the Brier calibration layer underneath.

The lesson I keep relearning: when the product is right and adoption is slow, look at the frame before the feature list.

council-diff is MIT, on npm, and drops into any `.claude/skills/` directory. ~$0.03 per council deliberation, ~$0.10 with Fable 5 Oracle adjudication.
