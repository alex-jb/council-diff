**Body (≤300 words):**

Karpathy at Sequoia (April 2026):

> "Traditional software automates what you can specify. AI automates what you can verify."

His agentic engineering job description: design specs, supervise plans, inspect diffs, write tests, **create evaluation loops**, manage permissions, isolate worktrees, preserve quality.

council-diff is one OSS library that maps directly onto that bullet:

| Karpathy's job description | council-diff primitive |
|---|---|
| Specs precise enough that ambiguity hides nowhere | 5 persona briefs per domain |
| Inspect diffs | Voice verdicts side by side |
| Write tests | `agreement_score`, 1.0 unanimous → 0.0 split |
| **Create evaluation loops** | **Brier audit. Every voice scored at resolution** |
| Manage permissions | `safeMode: true` forces zero-retention Sonnet 4.6 |
| Preserve quality | Fable 5 Oracle adjudicates and overrides |

Paste a decision, get 5 specialist verdicts in parallel from the same model (different personas, not different providers, that is Perplexity Model Council's surface). Optionally let Fable 5 read all 5 and override. Then Brier-audit every voice at resolution.

What it is NOT: not an agent framework, not a tool wrapper, not an orchestrator. One library, one call, 5 verdicts, optionally one adjudicator. ~$0.03 council-only, ~$0.10 with Oracle.

What is different from Anthropic's "advisor strategy" (beta, 2026-06-09): same pattern, shipped 6 months earlier, still the only OSS implementation that ships the Brier calibration layer underneath. Drop council-diff into any `.claude/skills/` directory and it auto-loads.

Pre-empting the wrapper rebuttal: yes, this calls Claude. The point is the evaluation loop (Brier audit + Oracle override + retention disclosure), not the API call. Without those three layers, multi-persona prompts are just chatter.
